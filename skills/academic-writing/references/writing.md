# 学术写作的论证逻辑

> **来源说明**：本文档写作时环境里的联网检索工具不可用，内容出自编写者
> 掌握的知识。为了让你能判断可信度，下面区分三类：
> 【实证】有语料研究、对照实验或心理语言学实验支撑，给了出处；
> 【惯例】学界广泛共识但无实验证据；
> 【民间】流传很广但站不住甚至是误传——列出来是让你别照做。
>
> `paper.md` / `report.md` 讲各节该放什么，本文讲**为什么这么排、句子怎么写**。

---

## 零、一句话的核心

**论文是一个论证，不是工作记录。**

做实验的顺序和写论文的顺序不一样。读者不关心你先试了什么后试了什么，
他们要回答的只有一个问题：**凭什么相信你的结论**。

所以写之前先答三句话，答不出来就不要开始写：

1. 我的主张是什么？（一句话，带数字）
2. 支撑它的证据是什么？（列 2~3 条）
3. 最可能的反驳是什么？我怎么挡？

这三句写不出来，说明工作本身还没想清楚，这时候动笔只会把混乱固化成文字。

## 一、引言的骨架：CARS 模型 【实证】

出处：John M. Swales, *Genre Analysis: English in Academic and Research
Settings* (1990)。这是基于**大量真实论文引言的语料分析**总结出来的结构，
不是拍脑袋的建议。CARS = Create A Research Space。

三个动作（Move），顺序不能换：

| Move | 做什么 | 典型写法 |
|---|---|---|
| **1 确立领域** | 说明这个问题重要、有人在做 | 「X 是……的关键环节」「近年来 X 受到广泛关注」 |
| **2 指出空隙** | **说清楚现有工作差在哪** | 「然而，现有方法在……时存在……」 |
| **3 占据空隙** | 宣告本文做了什么 | 「针对上述问题，本文提出……」 |

**Move 2 是全篇的支点，也是最容易写砸的地方。**

写砸的典型：

> ✗ 然而，现有方法的性能仍有提升空间。
> ✗ 但是这些方法效果不够理想。

这两句等于没说——任何一篇论文都可以放这句。空隙必须具体到**机制**：

> ✓ 然而，特征金字塔的横向连接采用固定权重相加，未考虑不同空间位置
>   对各层级特征的需求差异——背景区域与小目标区域被同等对待。

判断标准：**把你的 Move 2 抄出来，看它能不能被别人的论文原样复用**。
能，就说明写虚了。

Move 2 有四种合法的写法，选一种：

- **反驳**：现有结论在某条件下不成立
- **空白**：某个问题还没人做
- **延伸**：现有方法可以推广到新场景
- **矛盾**：两条已有结论互相冲突

其中「空白」最弱——「没人做过」不等于「值得做」，用它时必须补一句
为什么值得做。

### 引言不是文献综述 【惯例】

这是中文论文里最常见的结构错误。引言里提到文献是为了**支撑 Move 1 和
Move 2**，不是为了展示读得多。判断方法：删掉某篇引用，如果论证不受影响，
那篇就不该在引言里，应该挪到相关工作。

## 二、句子怎么写：读者期待 【实证】

出处：George Gopen & Judith Swan, "The Science of Scientific Writing",
*American Scientist* 78 (1990)。这是科学写作领域被引用最多的文章之一，
核心洞察是：**读者在读到内容之前，就已经对信息出现的位置有了期待**。
写作的任务是把内容放到读者期待它出现的位置。

### 2.1 句首放旧信息，句末放新信息

心理语言学基础：Haviland & Clark (1974) 的 Given-New 契约实验证明，
读者处理句子时会先寻找已知信息作为锚点，再挂接新信息。

- **句首（topic position）**：放与上文的连接、读者已知的东西
- **句末（stress position）**：放本句最重要的新信息

对比：

> ✗ 由于门控权重按空间位置自适应，小目标区域保留了更多浅层信息，
>   这是本文方法有效的原因。
>
> ✓ 门控权重按空间位置自适应，使小目标区域保留了更多浅层信息——
>   **这正是精度提升的来源**。

第二句把结论放在了句末重音位置。**每写完一段，检查每句话的最后几个词
是不是你最想让读者记住的。**

### 2.2 主语和动词要靠近

读者在找到动词之前，会一直把主语挂在工作记忆里。中间塞得越多越累。

> ✗ 本文提出的基于跨层注意力门控与可变形卷积对齐的多尺度特征融合方法，
>   在遥感图像目标检测任务上，**取得**了显著的性能提升。
>
> ✓ 本文提出多尺度特征融合方法，它用跨层注意力门控与可变形对齐两个模块
>   处理特征错位。在遥感目标检测上，该方法**将** mAP **提升** 3.7 个百分点。

中文的定语在前，长定语会把主语和动词推得很远——这是中文学术写作的
结构性难点，只能靠**拆句**解决，不能靠调语序。

### 2.3 让角色当主语，让动作当动词 【惯例】

出处：Joseph Williams, *Style: Lessons in Clarity and Grace*。这是写作技艺
而非实验结论，但极其有效。

名词化（把动作写成名词）是学术中文的头号病灶：

| ✗ 名词化 | ✓ 动词化 |
|---|---|
| 对该方法进行了改进 | 改进了该方法 |
| 进行了实验的设计 | 设计了实验 |
| 实现了对精度的提升 | 把精度提升了 3.7 个百分点 |
| 完成了数据的采集工作 | 采集了数据 |

**自查**：搜「进行」「实现」「完成」「开展」「作出」，
后面跟名词的基本都能改。这一条改完，全文能短 10%~15%，且更好读。

## 三、被广泛相信但站不住的 【民间】

- **「学术写作应该用被动语态，显得客观」** —— 现在多数期刊（含 *Nature*、
  *Science* 的作者指南）明确鼓励主动语态。被动语态把施动者藏起来，
  导致主语和动词分离，反而更难读。中文里的「被……所……」尤其别扭。
  该用被动的场合只有一个：**施动者不重要或未知**（「样本被随机分为两组」）。

- **「不能用『我们』」** —— 多数英文期刊允许甚至鼓励 "we"。中文期刊
  确实更倾向无主语句，但解法是改成无主语（「本文提出」→「提出」），
  不是改成被动。

- **「用复杂的词显得专业」** —— 有实验反证：Oppenheimer (2006) 的研究
  *Consequences of Erudite Vernacular Utilized Irrespective of Necessity*
  发现，**不必要的复杂用词会降低读者对作者智力的评价**。写得清楚不会
  让你显得浅薄，只会让你显得想清楚了。

- **「引言要写得越全面越好」** —— 引言的长度不是学识的证明。
  CARS 三个 Move 走完就该停，通常 1~1.5 页。

## 四、段落

【惯例】但可操作性很强：

- **一段一个论点。** 一段讲不完就是两个论点，拆开。
- **主题句放段首。** 英文学术段落是演绎式（先结论后论据），
  这与中文传统的归纳式（先铺垫后结论）相反。写中文论文时也建议用演绎式，
  因为科技写作的读者是**扫读**的，他们靠段首句决定这段要不要细读。
- **段间连接靠内容，不靠「首先/其次/最后」。**
  「首先其次最后」只说明有顺序，不说明**为什么是这个顺序**。
  换成有信息量的连接：「上述方法都假设……，而这一假设在……时不成立」。

**反向提纲（reverse outline）** 是检验段落逻辑最有效的方法：把已经写好的
每一段抽成一句话，列成一张表，读这张表看逻辑通不通。
skill 里有脚本自动做这件事：

```bash
uv run python "$TPL/skills/academic-writing/scripts/outline.py" <项目目录>
```

## 五、论文和技术报告的逻辑不一样

这是很多人把报告写成论文（或反过来）的根源：

| | 学术论文 | 技术报告 |
|---|---|---|
| 回答什么 | 凭什么相信这个**新知识主张** | 这项工作**做了什么、结论是什么、怎么复用** |
| 读者 | 同行评议者，会挑刺 | 委托方、接手的工程师、半年后的你自己 |
| 核心诉求 | 新颖性、正确性、对比公平 | 可复现、可追溯、决策依据充分 |
| 失败的尝试 | 通常不写 | **应该写**，能省下别人重走弯路的时间 |
| 负结果 | 难发表 | 是有价值的交付物 |
| 篇幅取向 | 越紧越好，删到不能再删 | 完整优先，附录可以很长 |
| 结论的语气 | 谨慎，不外推 | 明确给出建议与适用边界 |

**推论**：技术报告里可以、也应该有「我们试过 X，不work，原因是 Y」这样的
一节。论文里写这个通常是减分（除非它本身是贡献），报告里写这个是加分。

**另一个推论**：报告要写清楚「换个人接手需要知道什么」——环境版本、
数据在哪、脚本怎么跑、哪些参数是拍的哪些是调的。论文不需要这些细节，
报告缺了这些就等于没交付。

## 六、论证上的常见硬伤

按审稿人最爱挑的顺序：

1. **相关当因果。** 「加了模块 A 后精度提升，说明 A 有效」——
   只有在**其他条件严格不变**时才成立。控制变量没做干净，这句就不成立。

2. **消融不完整就宣称模块有效。** 有 A+B 的结果和 baseline 的结果，
   不能推出 A 和 B 各自的贡献。要么补单独消融，要么把主张收窄成
   「A 与 B 的组合有效」。

3. **结论超出证据范围（overclaim）。**
   在一个数据集上验证，结论就只能说「在该数据集上」。
   写「本方法普遍优于……」而只测了一个数据集，是最容易被逮住的错误。

4. **基线不公平。** 对比方法用原论文的数字而自己的方法用调过的配置，
   或者对比方法没用相同的骨干/数据增强。**要么全部自己复现，
   要么明确标注哪些是引用数字**。

5. **Cherry-picking。** 只报最好的一次运行。解法是给重复次数和波动范围
   （见 `report.md` 的不确定度评定）。

6. **「首次」的风险。** 「本文首次提出……」一旦被找到反例，
   审稿人对全文的信任都会崩。除非做过系统检索并能拿出证据，
   否则改成「据我们所知」，或者干脆不写。

7. **相关工作写成流水账。** 列了 30 篇，但没有一句说清共同局限。
   审稿人由此判断「作者没读懂这个领域」。

## 七、改稿：先结构后句子

顺序反了会做大量无用功——句子打磨完再发现整段要删，那些功夫全白费。

1. **反向提纲**（结构层）。用上面的脚本或手工，把每段抽一句，
   读这张表。问三个问题：顺序对吗？有没有两段在说同一件事？
   有没有断层（从 A 跳到 C，缺了 B）？

2. **段落层**。每段的主题句在不在段首？一段是不是只有一个论点？

3. **句子层**。这时候才做 §2 的三件事：句末重音、主谓靠近、去名词化。

4. **词汇层**。术语全文统一（同一个概念不要一会儿叫「模块」一会儿叫「组件」）；
   删掉「基本上」「相对来说」「一定程度上」这类模糊词。

**两个便宜且有效的技巧** 【惯例】：

- **大声读出来。** 读着卡住的地方，读者也会卡。
- **倒着读段落**（从最后一段往前读）。正着读会被上文的语境带着走，
  觉得处处通顺；倒着读能暴露出「这段其实没交代清楚」。

## 八、审稿人在找什么 【惯例】

理解这个能让你在写的时候就把防线布好。审稿人按这个顺序过：

1. **这篇的主张是什么？** —— 摘要和引言 Move 3 里找。找不到就直接负面。
2. **这个主张新吗？** —— 相关工作 + Move 2。这里模糊，审稿人会自己去搜，
   搜到相似工作就麻烦了。
3. **证据支持这个主张吗？** —— 实验设计是否能排除其他解释。
4. **实验公平吗？** —— 基线、数据划分、调参预算。
5. **作者知道自己的边界吗？** —— 局限一节。**主动写局限是加分项**，
   它证明你理解自己做了什么。

所以写作时的防守顺序应该反过来：先确保 3 和 4 站得住，再打磨 1 和 2 的表述。

## 九、自查清单

**结构层**
- [ ] 三句话能说清：主张 / 证据 / 最可能的反驳
- [ ] 引言的 Move 2 具体到机制，不能被别人的论文原样复用
- [ ] 引言不是文献综述——删掉某篇引用会影响论证吗
- [ ] 反向提纲读下来逻辑连贯，没有断层与重复
- [ ] 结论与引言的贡献列表逐条对应

**论证层**
- [ ] 每个「A 导致 B」都有控制变量支撑
- [ ] 宣称模块有效的地方都有单独消融
- [ ] 结论的适用范围不超过实验覆盖的范围
- [ ] 对比方法的配置说明了是复现还是引用
- [ ] 主结果有重复次数与波动范围
- [ ] 有单独一段写局限

**文字层**
- [ ] 搜「进行 / 实现 / 完成 / 开展」，名词化都改成了动词
- [ ] 每段主题句在段首
- [ ] 关键句的重要信息在句末
- [ ] 术语全文统一
- [ ] 段间连接有信息量，不是「首先其次最后」

**技术报告额外**
- [ ] 写清楚了换人接手需要知道什么（环境、数据、脚本、参数来源）
- [ ] 失败的尝试与负结果有交代
- [ ] 结论给出了明确建议与适用边界
